# Exemplo 3: Decisão condicional (if)

## Código C

```c
int maior(int a, int b) {
    if (a > b) {
        return a;
    } else {
        return b;
    }
}
```

## Assembly gerado (x86-64, -O0)

```nasm
; ...
"maior":
	push	rbp
	mov	rbp, rsp
	mov	DWORD PTR 16[rbp], ecx
	mov	DWORD PTR 24[rbp], edx
	mov	eax, DWORD PTR 16[rbp]
	cmp	eax, DWORD PTR 24[rbp]
	jle	.L2
	mov	eax, DWORD PTR 16[rbp]
	jmp	.L3
.L2:
	mov	eax, DWORD PTR 24[rbp]
.L3:
	pop	rbp
	ret
```

## Correspondência C → Assembly

| Linha em C | Instruções assembly | O que faz |
|---|---|---|
| `if (a > b)` | `mov eax, 16[rbp]` / `cmp eax, 24[rbp]` / `jle .L2` | Compara `a` e `b` e desvia se `a <= b` |
| `return a;` | `mov eax, 16[rbp]` / `jmp .L3` | Caminho verdadeiro: retorna `a` |
| `return b;` (else) | `.L2:` `mov eax, 24[rbp]` | Caminho falso: retorna `b` |
| fim | `.L3:` `pop rbp` / `ret` | Ponto de junção e retorno |

## Explicação

A tradução de um `if/else` segue o padrão comparação + salto condicional. A instrução `cmp eax, 24[rbp]` subtrai internamente `b` de `a` apenas para atualizar as *flags*; o resultado não é guardado. Em seguida, `jle .L2` consulta essas flags: se `a <= b` (ou seja, a condição `a > b` é falsa), o fluxo desvia para o ramo `else`.

Repare que a lógica foi invertida: o código C testa `a > b`, mas o assembly salta quando `a <= b`. Essa inversão é comum, pois organiza o código de modo que o caminho "verdadeiro" siga em sequência (sem salto) e o "falso" fique no destino do desvio. O rótulo `.L3` é o ponto de junção onde os dois caminhos reconvergem antes do `ret`.

Como `maior` só lê os parâmetros e não tem variáveis locais, o prólogo é mínimo (`push rbp` / `mov rbp, rsp`), sem `sub rsp`.

## Comparação -O0 vs. -O2

```nasm
"maior":
	cmp	ecx, edx
	mov	eax, edx
	cmovge	eax, ecx
	ret
```

Com `-O2`, o desvio condicional desaparece. O GCC usa `cmovge` (*conditional move*): carrega `b` em `eax` e, se `a >= b`, move `a` para `eax`. O resultado é código sem salto (*branchless*), que evita o risco de erro de predição de desvio no pipeline. A contagem cai de 12 para 4 instruções, e não há acesso à pilha.

## Comparação CISC vs. RISC

Assembly RISC-V não gerado neste trabalho; comparação teórica. RISC-V não possui `cmov`: a seleção de máximo seria tipicamente expressa com um desvio condicional (`blt`/`bge`) sobre registradores previamente carregados, ou com sequências que combinam comparação e seleção. O `cmp` do x86, que apenas atualiza flags, corresponde em RISC-V a instruções que comparam e já decidem o salto em um único passo (`blt a, b, destino`), sem um registrador de flags separado.

## Ligação com a ementa

- **I.6 Tipos de instruções:** instruções de controle de fluxo (`cmp`, `jle`, `jmp`).
- **V.2.3 Dependência de controle:** o salto condicional cria uma dependência de controle — o processador só sabe o próximo caminho após avaliar a condição, tema central do pipeline.
